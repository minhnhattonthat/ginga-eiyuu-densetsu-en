# Text engine

ROM: LoROM 1 MB ($00-$1F), no header, SRAM 8 KB. File offset = ((bank & 0x7F) << 15) | (addr & 0x7FFF).

## Encoding (verified: decodes ＬＯＡＤかＮＥＷを/選択してください at 0x2848A, the title menu text; tbl/jp.tbl)

- One byte `00-CF` = glyph index. `D0-DF xx` = glyph `0xD0 + (c & 0x0F) * 0x100 + xx` (only D0/D1 used: glyphs
  0xD0-0x1FE). Code in $07:9B66 / $07:9B71.
- Glyph order: 00 blank, 01-2E あ..ん (gojuon), 2F-37 small ぁぃぅぇぉっゃゅょ, 38-65 ア..ン, 66-6E small ァ..ョ,
  6F-88 A-Z, 89-92 0-9, 93-A9 punctuation, AA-C2 voiced/semi-voiced hiragana, C3-DB voiced katakana, DC “ DD ”
  DE ヴ DF ：, E0-1FE kanji. Table generated by `tools/mk_jp_tbl.py` (kanji read off `tools/font_sheet.py`).
  Guesses still to confirm in context: 1AA 業, 1BA 水, 1D8 second 亡 (written 亾 in the table).
- Control codes (interpreter $07:993A, byte fetch $07:9DE3 from the 24-bit pointer $1113-$1115):
  - `E0 nn` call substring nn from the 16-bit table at ($1177-$1179) = $05:FF00 (only E0 is usable: E1-EF index
    $117B+, the saved return pointer). Ids 00-05 point at RAM $1F10/$1F20/.../$1F60 (16-byte name buffers filled by
    $00:F46B from the bank-$02 tables), 06-17 at fixed strings $05:FF30-FFB5.
  - `F0 a b` set $1199/$119A. `F1 x y` set position ($1173/$1175) and return. `F2 n`, `F3 n` argument skipped.
    `F4 n` wait n (sets $1171). `F5 n` page/advance. `F6 n` speed. `F7 n` sets $119C = n*4+$20 (colour/palette?).
  - `FC` end with box advance, `FD` wait for key / close, `FE` newline, `FF` end (or return from substring).
    F8-FB behave as FF.

## Main script (verified: whole table decodes with no gaps)

- Opener `JSL $07:979F` (PHP; X = message id). Pointer table $05:8000 = file 0x28000, 571 x 16-bit (bank $05).
  Strings 0x28476-0x2F882, contiguous. 45 direct call sites (`A2 nn nn 22 9F 97 07`); the rest come from event
  scripts.
- Substring table $05:FF00 (24 entries), strings to ~0x2FFB5. Free: 0x2F883-0x2FEFF (0xFF fill, 1661 bytes),
  ~0x2FFB6-0x2FFFF.

## Name tables (bank $02, verified by the copy routine $00:F46B)

Format: `len` (chars + 1) then chars then `FF`. Copied into 16-byte RAM slots, so 15 bytes max per name unless the
slots move.

## Rebuild regions (`tools/build.py`, verified: identity build + `tests/test_identity.py`)

- Main strings repack into 0x28476-0x2FEFF in their original order (not id order), then 0xFF fill; sub strings
  into 0x2FF30-0x2FFFF. Main has 1661 bytes of slack, sub ~72.
- Name tables repack in place, each into [end of its pointer table, end of its last string): **zero slack**, so any
  longer name needs relocation (bank $02 0xFF tail 0x16DEA-0x17FFF, 4630 bytes: candidate, trap-test first).
  `side_0/1` live inside bank $00 code: 8 bytes each, fixed.
- Graphics compressor (`tools/gfx.py compress`) recompresses 355/356 blocks byte for byte; 0D_0A stores a redundant
  zero row (decodes the same).

## Extraction coverage (verified: `tests/test_roundtrip.py`)

- Every main/sub/name string decodes and re-encodes to its original bytes; `script/*.json` jp matches the ROM.
- Main: pointer table, then strings back to back to 0x2F882, 0xFF to 0x2FEFF. Sub: table 0x2FF00, strings
  0x2FF30-0x2FFB7, 0xFF to the bank end. Names: the five tables sit back to back 0x103BB-0x1081B, each pointer table
  followed by its strings with no gap; the bytes around them are numeric tables.
- The string pointer $1113-$1115 has exactly four writers, all in bank $07: the opener (main table, $07:97D0),
  substring call ($07:9B4C) and return ($07:9A41), byte advance ($07:9E0C); the font bank is read only through
  $1116 ($07:9AC1). So the 12px renderer has no text source beyond main/sub (plus the RAM name slots); other
  on-screen Japanese is graphics (graphics.md). A whole-ROM `jp_left.py --tbl` sweep is useless here: with a
  one-byte encoding every bank decodes as kana (25,159 runs in the original).

## Renderer

- 12x16 glyphs, 1bpp, 32 bytes each (8x8 tiles TL, TR, BL, BR; 12 px used) at $06:8000 = file 0x30000.
  Glyphs 0x000-0x1FE used, 0x1FF-0x21F blank, 0x220-0x3FF (file 0x34400-0x37FFF) all 0xFF: free-space candidate.
- Draws into a 2bpp BG3 tile canvas (title box: 26 x 4 tiles at tile $2B0); odd glyphs are shifted 4 px and ORed
  (fixed 12 px pitch). VRAM is shadowed in WRAM $7F:0000-FFFF and DMAd whole.

## Graphics compression (verified: disassembly of $00:9272 / $00:92DD)

Per 8x8 tile: one mask byte per plane (bit set = row non-zero), then the non-zero row bytes. $00:9272 = 2bpp,
$00:92DD = 3 planes. Source [$A3], dest [$26], tile count $2E. Officer names and ranks on the fleet panel are
pre-rendered tiles in this format (graphics text, see graphics.md).
